# CROSS-LANGUAGE-002 — CANONICAL-002 Execution Evidence

Scope: conformance only. No production runtime, hashing, Merkle core or
protocol semantics were modified in either repository.

Task: **DQ-006-R1** — supply the JCS-discriminating cross-language fixture that
CANONICAL-001 could not provide.

## Why this fixture exists

CANONICAL-001 is **JCS-degenerate**. For that object,
`json.dumps(obj, sort_keys=True, separators=(",", ":"))` produces bytes
identical to the RFC 8785 output, and therefore the identical SHA-256 and the
identical RFC 6962 leaf. CROSS-LANGUAGE-001 consequently establishes that RI-PY
and RI-RS *agree*; it does not establish that either *implements RFC 8785*.

CANONICAL-002 is built so the two provably diverge.

| Case | Property | RFC 8785 | Ordinary sorted JSON |
| --- | --- | --- | --- |
| A | Member ordering | UTF-16 code unit | code point |
| B | Non-ASCII | raw UTF-8 | `\uXXXX` (default `ensure_ascii`) |
| C | `1.0` | `1` | `1.0` |
| D | `-0.0` | `0` | `-0.0` |
| E | `1e-7` / `1e-6` | `1e-7` / `0.000001` | `1e-07` / `1e-06` |
| F | Nested members | canonicalised recursively | — |
| G | Array order | preserved | preserved |
| H | Escaping | minimal; solidus unescaped | — |

Case A is the sharpest. `U+10000` encodes as the surrogate pair `D800 DC00`, so
its first UTF-16 code unit (`0xD800`) is *smaller* than `U+FB00` and `U+FFFF`
even though its code point is larger. RFC 8785 must sort it before them; a
code-point sort must place it after.

## Independence

The two artifacts were produced by separate toolchains, in separate
repositories, from separate JCS engines. Neither side reads the other:

* `emit_ri_py_artifact.py` imports only the RI-PY adapter. It reads no frozen
  reference constant and no RI-RS file.
* `conformance/canonical/canonical_002.rs` references no RI-PY value, path or
  artifact, and carries **no expected hex constant at all** — it asserts
  observable RFC 8785 properties of the bytes the engine produced. The artifact
  is written before its assertions run, so a divergence would have been
  recorded rather than suppressed.
* Neither artifact was edited after generation.

The frozen reference values in `manifest.json` were established *by* this
agreement: `emit_manifest_002.py` refuses to write a manifest unless RI-PY and
RI-RS independently produced identical bytes, digest and leaf, and refuses to
write one if the fixture turns out to be JCS-degenerate.

## Independent verification

Distinguishing **engine output** from **independent verification**:

*Engine output* — the canonical bytes above, produced by `rfc8785` 0.1.4 and by
`serde_json_canonicalizer` 0.3.2.

*Independent verification* — performed without either engine:

1. Both digests recomputed by the gate from the decoded hex, on each side
   separately (CHECK 2, 3, 5, 6).
2. The canonical bytes decoded and inspected structurally: member order,
   number forms, escaping and array order read directly out of the byte
   sequence.
3. The UTF-16 ordering premise verified arithmetically —
   `"\U00010000".encode("utf-16-be")[:2] < "ﬀ".encode("utf-16-be")[:2]` while
   `ord("\U00010000") > ord("ﬀ")`.
4. The sorted-JSON negative reference computed and shown to differ (716 bytes
   vs 655).

No fully independent third RFC 8785 implementation was available in this
environment. **Stated explicitly:** the two agreeing engines plus the structural
and arithmetic checks above are the independent basis; there is no third-party
oracle for CANONICAL-002.

## Artifact provenance

Following the CANONICAL-001 separation, and addressing the self-reference
problem directly:

| Repository | Execution commit (recorded in artifact) | Artifact commit |
| --- | --- | --- |
| RI-PY | `7bcc600f649a35f76cee5752ce597ac2b71b6d62` | see git history |
| RI-RS | `bd4a2fa6b4d11dcfb270b4a4f98b2f359ab32609` | `5685b2a74ca2fabcdbcf36c89733c42ba0141f7e` |

Each artifact records the clean-worktree commit that produced it, never its own
publication commit, so no artifact hash is self-referential. Both artifacts
record `worktree_clean: true`.

**Evidence infrastructure debt (not a protocol failure).** Re-running either
emitter at a later commit rewrites `commit` and `worktree_clean` in the
artifact, so the artifact *file* digest is not stable across reruns even though
the canonical bytes, digest and leaf are fully deterministic. The corpus
therefore cannot be verified by file digest alone; it must be verified by
re-execution and byte comparison, which is what the gate does. Making artifact
files reproducible byte-for-byte would require separating execution metadata
from canonical evidence — a corpus-architecture change, deliberately not made
here.

## Verdict

`CROSS-LANGUAGE-002: PASS` — RI-PY and RI-RS produce byte-identical
CANONICAL-002 canonical bytes, SHA-256 and RFC 6962 leaf under independent
execution, on a fixture where an ordinary sorted-JSON serializer provably
diverges and is rejected by the gate.

This evidence is submitted for DQ-006-R1. It does not itself close DQ-006.
