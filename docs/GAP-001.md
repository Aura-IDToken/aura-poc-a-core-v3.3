## 1. Executive Summary

This document is the official implementation analysis for the `aura-poc-a-core` repository measured against the canonical Aura Protocol Specification (`spec-v0.1.0`). It is an analysis artefact. No source code has been modified by this document. No protocol behaviour has been invented.

The repository is a **research-backed prototype** at low implementation maturity. Three categories of finding drive this report:

1. **Critical violations** — components present in the repository actively contradict the specification and the mandatory invariants declared in the repository's own directives (ADR-005, custom instruction). **GAP-C1 through GAP-C4 are RESOLVED as of CORE-005 (2026-07-24). GAP-C5 is partially resolved.**

2. **Partial implementations** — components exist but are incomplete, not wired together, or implemented only for demonstration purposes.

3. **Missing components** — required protocol components have no implementation at all.

A total of **27 CORE tasks** were identified. CORE-005 is complete. The remaining 22 tasks are open.

## 4. Gap Analysis

### 4.1 CRITICAL — Invariant Violations (RESOLVED by CORE-005)

> ✅ **All items in this section are RESOLVED as of CORE-005 (2026-07-24).**  
> They are retained for audit traceability. See CORE-005-IMPLEMENTATION-REPORT.md for verification results.

#### GAP-C1: Float Arithmetic in `core/evaluator.py` — ✅ RESOLVED

**Previously:** `core/evaluator.py` contained `import math` and `math.sqrt` in cosine similarity computation.

**Resolution (CORE-003):** `core/evaluator.py` now uses integer-only arithmetic. `PoCAEvaluator.evaluate()` accepts pre-normalised int32 vectors and performs only integer dot product, scaling, and clamping. No float operations remain.

**Verification:** `check_2_integer_only.sh` PASSED.

#### GAP-C2: Float Arithmetic in `core/consistency.py` — ✅ RESOLVED

**Previously:** `core/consistency.py` contained `import math` and `math.sqrt`.

**Resolution (CORE-004):** `core/consistency.py` is now a deprecated backward-compatibility wrapper that re-exports `ConsistencyCalculator` from `compliance/consistency.py`. The `compliance/consistency.py` implementation uses integer arithmetic only. The deprecated wrapper will be removed in v4.0.

**Verification:** `check_2_integer_only.sh` PASSED.

#### GAP-C3: Policy Logic in Layer 0 (`core/evaluator.py`) — ✅ RESOLVED

**Previously:** `core/evaluator.py` contained `COMPLIANCE_THRESHOLD = 0.8` and returned `"status": "COMPLIANT" if ari > self.COMPLIANCE_THRESHOLD else "RISK"`.

**Resolution (CORE-005):** The `status` field and `COMPLIANCE_THRESHOLD` constant have been removed from `core/evaluator.py`. The method now returns only `{"ari": <int32>, "drift": <int32>}`. Policy decisions are handled exclusively by `compliance/evaluator_wrapper.py`.

**Verification:** `check_3_layer_separation.sh` PASSED.

#### GAP-C4: Policy Logic in Layer 0 (`core/policy.py`) — ✅ RESOLVED

**Previously:** `core/policy.py` contained `RegulatoryPolicy`, `PolicyRule`, and threshold constants inside Layer 0.

**Resolution (CORE-005):** `core/policy.py` is now a deprecated backward-compatibility wrapper that re-exports from `compliance/policy.py`. All policy logic resides in Layer 2. The deprecated wrapper will be removed in v4.0.

**Verification:** `check_3_layer_separation.sh` PASSED.

#### GAP-C5: Duplicate ARI Implementations — ✅ LARGELY RESOLVED

**Previously:** Two independent ARI implementations with divergent behaviour existed in `core/consistency.py` and `core/evaluator.py`.

**Resolution (CORE-005 / CORE-006 partial):** `core/evaluator.py` (`PoCAEvaluator`) is the canonical Layer 0 ARI engine. `core/consistency.py` is a deprecated wrapper to `compliance/consistency.py`. `compliance/consistency.py` (`ConsistencyCalculator`) provides a higher-level evaluation with policy integration but uses the same integer arithmetic approach. A formal CORE-006 consolidation (single canonical implementation) remains open for v4.0.

**Remaining gap:** `compliance/consistency.py` (`ConsistencyCalculator`) and `core/evaluator.py` (`PoCAEvaluator`) have overlapping responsibilities. CORE-006 (deferred to v4.0) should fully consolidate these.

### 4.2 HIGH — Missing Core Components

#### GAP-H1: Integer-Only ARI Engine (APS-200) — ⚠️ PARTIALLY RESOLVED

`core/evaluator.py` (`PoCAEvaluator`) now implements integer-only ARI computation via pre-normalised dot product (CORE-003 complete). However, no standalone `ari_engine.py` module exists as specified by CORE-010. The current implementation requires callers to pre-normalise vectors offline.

Required operations currently implemented:
- ✅ Integer dot product: `dot = sum(a * b for a, b in zip(v_int, c_int))`
- ✅ ARI formula in fixed-point: `ari = (30000 * si + 70000 * sa - penalty) // SCALING_FACTOR`

Required operations still absent:
- ❌ No standalone `ari_engine.py` module
- ❌ No integer magnitude comparison without pre-normalisation requirement

#### GAP-H2: No Canonical Event Schema / Fixture Format (APS-100, APS-900)

No normative event schema is defined. The `certificate_schema.json` is a sketch with placeholder values (`"uuid-v4"`, `"sha256"`, `"ISO-8601"`). No JSON Schema validator is present. Tests use ad-hoc vectors (`[0.5] * 10`). No fixture file format is defined or loaded.

#### GAP-H3: No Canonical Serialisation Module (APS-400)

No `serializer.py` or equivalent exists. The byte serialisation done in `test_bitwise_replay.py` (`value.to_bytes(4, byteorder='little', signed=True)`) is test-internal and not part of a reusable serialisation contract. The endianness convention (little-endian, int32) is not enforced at the protocol level.

#### GAP-H4: No Protocol Bootstrap (APS-000)

No protocol initialisation sequence exists. There is no:
- Protocol version constant
- Constitution registration mechanism
- Bootstrap validation on startup
- Version compatibility check

#### GAP-H5: No Conformance Runner (APS-900)

No conformance test runner exists. The test suite (`unittest`) validates individual units but does not:
- Load canonical test fixtures
- Verify bit-identical output against reference hashes
- Produce a structured pass/fail conformance report
- Enable third-party conformance testing

### 4.3 MEDIUM — Incomplete or Disconnected Components

#### GAP-M1: ZK Pipeline Absent (APS-500)

`packages/zk-passport/reputation_check.circom` is correctly written for v3.3 (integer scaling, Art. 5 enforcement). However:
- No `circom` compiler configuration
- No `snarkjs` setup or trusted setup ceremony artifacts
- No proof generation script
- No proof verification harness in Python
- No integration point between `core/` ARI output and ZK circuit input
- ZK circuit is not executable from the repository

#### GAP-M2: Merkle Layer Not Integrated (APS-300)

`audit/merkle.py` and `audit/verify.py` exist but are not connected to the ARI evaluation pipeline. The ETC stub in `core/merkle.py` generates a single-leaf "proof" that is not a real Merkle proof. The `AuraEventCertificate` in `compliance/certificate.py` accepts `merkle_root` and `leaf_hash` fields but there is no code that computes them from the `audit/` layer.

#### GAP-M3: Certificate Signature Missing

`compliance/certificate_schema.json` includes a `"signature": "base64"` field. The `AuraEventCertificate` dataclass has no signature field. The `fingerprint()` method produces a hash but there is no signing mechanism (key management, algorithm selection, signature embedding).

#### GAP-M4: Embedding Module is Non-Production

`core/embedding.py` implements a character-ordinal hash that is:
- Not semantically meaningful (does not embed text into a semantic space)
- Not frozen to any external model
- Not compatible with `constitution_vector` dimension requirements in production (returns `[0.0]*1536`, not int32)

> **Note:** `core/embedding.py` is a placeholder. Actual embeddings must be generated
> offline and pre-normalised via `core/offline_normalizer.py`. The offline step (float
> permitted per DET_01) produces int32 vectors for runtime use.

### 4.4 LOW — Documentation and Operational Gaps

#### GAP-M5: No Tests for Audit or Compliance Layers

`audit/` and `compliance/` have zero automated tests. The compliance reporter, certificate generation, Merkle tree construction, and proof verification are untested.

#### GAP-M6: CI Does Not Cover ARM or WASM

The GitHub Actions workflow only runs on `ubuntu-latest` (x86_64). The ARM runner is commented out. WASM testing is not present. The cross-platform bit-identity guarantee is architecturally designed to hold (integer-only arithmetic), but cannot be verified by CI until ARM/WASM runners are added.

#### GAP-M7: `VectorRepository.ts` Uses Float Cosine Distance

`packages/database-client/VectorRepository.ts` uses pgvector's `<=>` operator (float cosine distance). This is a Layer 2+ integration component and may not violate Layer 0 invariants, but the semantic gap between pgvector float similarity and the int32 ARI computation is undocumented. No adapter exists to convert pgvector similarity to int32 ARI space.

### 4.5 LOW — Documentation and Operational Gaps

#### GAP-L1: `docs/LEGACY_PROTOCOL.md` is Empty

Content: `# LEGACY PROTOCOL ADDED`. No actual content. This gap reduces traceability.

#### GAP-L2: No Version Manager

No component tracks protocol version, schema version, or compatibility matrix. The `pyproject.toml` declares `version = "0.1.0"` but this is not referenced at runtime.

#### GAP-L3: No Registry

No component registry maps APS IDs to implemented modules or tracks implementation status programmatically.

#### GAP-L4: No Traceability System

No system links evaluation outputs to input events by persistent identifier. Certificates are not persisted. No event ID chain.

#### GAP-L5: `infra/docker-compose.yml` Has Hardcoded Credential

```yaml
POSTGRES_PASSWORD: ${DB_PASSWORD:-cathedral_secure}
```
The fallback value `cathedral_secure` is a default credential embedded in infrastructure configuration. This is not a runtime secret but poses an operational risk if deployed with defaults.

## 7. Risk Assessment

### 7.1 Critical Risks

| Risk | Category | Severity | Description |
|------|----------|----------|-------------|
| RISK-001 | Implementation | **Critical** | `core/evaluator.py` and `core/consistency.py` use `math.sqrt` and float arithmetic. The zero-float invariant is violated. Any measurement output from the current codebase is non-reproducible across platforms and cannot be claimed as metrologically valid. |
| RISK-002 | Compliance | **Critical** | `core/evaluator.py` returns `"COMPLIANT"/"RISK"` status from Layer 0. This violates layer separation. The automated checks (`check_3`) would detect this. Any merge to main with this code present would fail mandatory checks. |
| RISK-003 | Specification | **Critical** | The `aura-specification` repository is not present in this environment. APS-000 through APS-950 requirements are inferred from in-repo documentation. If the actual spec diverges from what is documented here, gap coverage may be incomplete. |

### 7.2 High Risks

| Risk | Category | Severity | Description |
|------|----------|----------|-------------|
| RISK-004 | Implementation | **High** | Two ARI implementations (`consistency.py`, `evaluator.py`) co-exist with subtly different cosine similarity normalisation (one offsets by `+1.0`/`2.0`, one does not). This creates ambiguity about which is canonical. |
| RISK-005 | Compliance | **High** | The `infra/docker-compose.yml` default credential (`cathedral_secure`) will be used in any deployment that does not set `DB_PASSWORD`. This is an operational security risk. |
| RISK-006 | Architecture | **High** | `core/policy.py` is inside the measurement layer. All downstream code that imports from `core.policy` will need refactoring when CORE-005 moves it. Refactoring risk is proportional to import surface. |
| RISK-007 | Implementation | **High** | The ZK circuit (`reputation_check.circom`) cannot be compiled or executed from this repository. There is no `circom` toolchain. The entire APS-500 component is unverifiable without CORE-017. |
| RISK-008 | Compliance | **High** | CI only runs on x86_64. The cross-platform bit-identity guarantee (BIT-IDENTITY IS LAW) cannot be verified or falsified in the current CI configuration. A bug that causes ARM divergence would not be caught. |

### 7.3 Medium Risks

| Risk | Category | Severity | Description |
|------|----------|----------|-------------|
| RISK-009 | Maintainability | **Medium** | `audit/` and `compliance/` layers have zero test coverage. Any change to these layers risks regression without detection. |
| RISK-010 | Implementation | **Medium** | `core/embedding.py` returns floats and uses character-ordinal values. If this function is called in a production path, it violates the zero-float invariant and produces semantically meaningless vectors. |
| RISK-011 | Architecture | **Medium** | `packages/database-client/VectorRepository.ts` uses pgvector float cosine similarity (`<=>` operator). The relationship between this float similarity and the int32 ARI computation is undocumented. There is a risk of semantic inconsistency between the database layer and the core engine. |
| RISK-012 | Specification | **Medium** | `docs/LEGACY_PROTOCOL.md` is a placeholder. If it is meant to document a deprecated protocol version, its absence reduces traceability and may create audit gaps. |

### 7.4 Low Risks

| Risk | Category | Severity | Description |
|------|----------|----------|-------------|
| RISK-013 | Maintainability | **Low** | Magic numbers (`0.3`, `0.7`, `0.8`, `0.68`, `1.5`, `1536`) are scattered across `evaluator.py`, `consistency.py`, and `policy.py`. CORE-001 addresses this. |
| RISK-014 | Security | **Low** | No input sanitisation is performed on `agent_id` before it is embedded in certificate output. If the agent_id contains control characters or special JSON characters, output rendering could be affected. |
| RISK-015 | Maintainability | **Low** | `pyproject.toml` declares no development dependencies. Installing the package for development requires manual knowledge of test tools. |
